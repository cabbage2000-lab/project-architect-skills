# 代码架构师

当前可执行的体检项是「必要文档」和「架构图」。在目标项目的编码助手会话中输入 `code-architect-skills` 默认检查两项。用户指定某一项时，在选定范围内执行该项。以当前仓库和会话中已有的维护任务为准，遵守用户限定的目录和读写权限。

1. 在检查前，按[项目规模与取证范围](references/project-size.md)盘点当前仓库，判断规模，记录依据并确定本轮优先核对的入口和模块。
2. 按[必要文档检查判据](references/necessary-documents.md)核对文档正文，按[架构图检查判据](references/architecture-diagrams.md)查找并对照图件。先核实各项是否适用，再沿同一入口找证据。分别记录维护者卡住的步骤、确切出处和未核实的资料。同一图件缺口保留在「架构图」。
3. 将证据分别交给 [necessary_docs.py](scripts/necessary_docs.py) 和 [architecture_diagrams.py](scripts/architecture_diagrams.py)，使用 `python3 -B` 通过标准输入传入检查记录，合并标准输出的 Markdown 章节。脚本路径相对于本 Skill，证据中的路径相对于目标仓库。合并时在首个章节记录一次项目规模。环境无法运行 Python 时，按各项判据交付相同的结论和建议。
4. 用户要求检查或体检时，交付诊断和修订位置。只读调用的取证操作须保持目标仓库只读。默认命令或用户要求修订时，从所选检查的已确认缺口中按交接影响合计选至多三项，说明优先理由，在已有授权内逐项修订。每项先记录原位置、可核实的操作、预期结果和回退办法。补图或修图时核对实际源文件、连线、对应代码与项目的导出约定。
5. 按新说明在本地实际走一次，记录操作、观察结果与差异。缺少验证条件的事项标为「待验证」并暂缓写入。出现回归时只撤回可独立分离的本项编辑，并复核回退结果。与他人编辑重叠时保留现场，继续处理独立事项。
6. 补写后重读实际章节，更新覆盖结论，保留初次缺口及其验证记录。导读给出新手下次从哪里开始、怎样自查。再次调用时从当前仓库重新判断规模并取证。

作为流水线的一项检查时，返回所选检查章节和已确认的候选，交给调用方合并。独立调用默认将本轮报告写入目标仓库的 `docs/code-architect-report.md` 并给出路径。用户限定只读、仓库不可写或同名报告含需保留的人工内容时，在会话交付全文。写入前复查目标，对来源或改动归属不明的已有内容也采用会话交付。
