# 项目规模与取证范围

在逐项检查前定位目标仓库根。先盘点文件列表、工作区清单和主要入口，取得规模依据。规模针对项目整体，本轮取证范围同时受维护任务和可见权限约束。

## 默认判据

- **独立维护单元**是可以独立运行、构建、测试或发布的应用、服务、工具或工作区包。根据工作区成员、入口和构建清单核实。单体项目算一个单元，其附属测试和内部目录归入该单元。
- **自维护文件**包含项目自有的源码、脚本、测试及手写的构建和部署配置。按仓库文件列表清点，排除第三方依赖、外部子仓库、生成物、缓存和资源文件。有 Git 时可用 `git ls-files --cached --others --exclude-standard` 列出文件，普通目录可用 `rg --files --hidden` 或等价命令。依据实际目录过滤、去重并记录计数口径。

| 规模 | 独立维护单元 | 自维护文件 |
| --- | --- | --- |
| 小项目 | 0–1 个 | 0–50 个 |
| 中等项目 | 2–5 个 | 51–500 个 |
| 大项目 | 6 个及以上 | 501 个及以上 |

两项落在不同档时取较大档。无法完整盘点的指标记为未知。任一已核实指标达到大项目档即可判为大项目，其余缺少指标的情形将规模标为「待确认」。只看到子目录时，记录可见边界，局部计数可用于说明取证范围。

在目标仓库用 `python3 <本 Skill 目录>/scripts/necessary_docs.py --project-size 2 80` 按独立维护单元数、自维护文件数的顺序判档。该例返回 `中等项目`，未知值用 `-`。也可直接按上表判档。

## 按规模确定检查范围

| 规模 | 取证方式 |
| --- | --- |
| 小项目 | 通查范围内的交接文档、入口、配置与验证方法，沿主要使用路径核对文档与实现。 |
| 中等项目 | 先查仓库级导读和共用流程，再查与维护任务相关的模块及其共用配置、接口和测试。一般交接按主要维护单元核对入口和各自的文档。 |
| 大项目 | 先建立仓库级文档与模块索引，再深查维护任务涉及的模块、上下游依赖和共享流程。一般交接优先走通主要业务路径，并标明未深入的模块。用户要求全项目检查时，按模块分批核对并汇总。 |
| 待确认 | 从可见范围内的主要入口和任务依赖开始，注明缺少的规模依据及其对结论的影响。 |

报告记录规模、两个计数、依据和本轮选定的范围。把计划范围与实际已查范围分别记录。对未查全的相关资料注明影响的检查项，结论写明适用的仓库级流程或具体模块。局部取证可以确认独立的局部缺口，仓库级缺失结论需要覆盖相关入口。
