# 治理计划

## 从体检发现确定本轮改动

1. 汇集本轮所选检查的发现及维护影响，引用仓库相对路径、符号或章节。同一改动能解决的多个发现合为一项，并保留各自的证据。例如同一方法的多类异味、多个章节提到的同一图件缺口。需要一起修改和回退的文件归入同一事项，写清改动范围。
2. 按当前维护任务的具体阻碍排列候选。没有指定任务时，优先处理直接妨碍启动、定位入口或验证改动的问题。优先选择证据充分、能独立验收和回退的事项，写明它为何值得本轮处理。
3. 给拟执行的事项记录最小改动范围、执行步骤和改前实测基线。先核对目标文件的当前内容及已有编辑，以原有入口、测试、固定输入或源码对照建立可重放的基线。验收写明操作、预期变化和需核对的行为。代码改动同时核对结构目标、主要调用方和用户可见行为。文档按说明实际操作，图件核对节点、连线和对应源码。回退写明恢复哪些位置、以哪个改前状态为准，以及怎样确认回退成功。
4. 业务规则或适用性仍需核实的事项记为「待确认」。缺少关键基线或验收条件时记为「待验证」。其他因本轮优先级、权限或回退条件暂时无法安排的事项记为「暂缓」。记录具体原因，继续处理相互独立的事项。只检查时使用可见证据提出建议，避免运行会写入目标仓库的基线操作。

每轮只生成一份计划，按最终计划顺序执行，最多三项。开始每项前重新核对证据、基线和工作区状态。已解决的事项跳过。证据、编辑或验收条件变化后，以当前状态重新判断，并在报告中记录跳过或暂缓的原因。保留原计划和实际复核记录，用计划项的序号和标题关联两者。

## 生成报告章节

用 `python3 -B <本 Skill 目录>/scripts/governance_plan.py` 从标准输入读取 UTF-8 JSON，或传入记录文件。宿主判断优先级和执行条件，脚本按提交顺序挑选前三个「可执行」事项，将其余发现和原因保留在同一 Markdown 章节。把该章节合并在体检章节之后、执行复核之前。

- `mode` 为 `execute`（本轮可在已有授权内修订）或 `inspect`（本轮仅检查或仓库只读）。`inspect` 的候选均显示「未执行」。
- `candidates` 按优先级排列，无候选时传 `[]`。每项含 `target`（合并后的唯一治理目标，可用路径及符号或章节表达）、`title`、非空 `evidence` 出处数组、`impact`、`status` 和 `reason`。`reason` 对执行项给出优先理由，对其余项说明受阻或暂缓原因。仅检查的候选可用 `status: "未执行"`，并说明该建议对应的检查目的或已知限制。
- `execute` 模式中，「可执行」事项还需 `scope`、`baseline`、`steps`、`acceptance` 和 `rollback` 五段非空文本。其余事项使用「待确认」「待验证」或「暂缓」。

### 最小示例

在本仓库根目录运行以下命令，样例中只纳入补写测试说明的事项。

```sh
python3 -B skills/project-architect-skills/scripts/governance_plan.py <<'JSON'
{
  "mode": "execute",
  "candidates": [
    {
      "target": "README.md#验证", "title": "补写最小验证步骤",
      "evidence": ["README.md#运行", "tests/test_names.py:6"],
      "impact": "接手者能运行项目，但缺少检查姓名排序的步骤。",
      "status": "可执行", "reason": "验证步骤直接服务于本轮交接。",
      "scope": "在 README.md 的运行章节补写测试命令和预期结果。",
      "baseline": "已读取运行章节并执行 `python3 -m unittest discover -s tests`，1 项通过。",
      "steps": "追加验证小节并记录实际通过的命令。",
      "acceptance": "按新小节运行命令，退出码为 0 且显示 1 项通过。",
      "rollback": "删去新增小节，与改前保存的 README.md 对照后重跑命令。"
    },
    {
      "target": "src/names.py::sort_names", "title": "核实同名输入的排序规则",
      "evidence": ["src/names.py:12", "src/import_names.py:18"],
      "impact": "合并相似的排序逻辑可能改变同名记录的次序。",
      "status": "待确认", "reason": "批量导入是否需要保留原始次序尚无业务依据。"
    }
  ]
}
JSON
```
