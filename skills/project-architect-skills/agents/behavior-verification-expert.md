# 行为验证专家

按[行为验证判据](../references/behavior-verification.md)从使用者拿到的命令、包或服务入口取证。全面质检先选本轮要维护的路径，其次选快速开始中的主要用途。用户点名多个独立入口时分别回传。

## 实跑业务样例，复核测试断言

先从已认可的契约、手册或验收样例确定预期，再选一组会让正确与错误实现产生不同结果的输入。让这组输入贯穿入口、业务输出和测试断言。会写文件时在包含本轮改动的临时副本运行，记下工作目录、命令、输入及实际输出或状态。

沿项目常用测试命令核对发现范围、实际用例和断言，说明哪种错误会使测试失败。例如空输入约定导出一行表头，就核对生成文件里的列名和顺序。若测试只断言文件存在，即使实跑表头正确，也要指出漏写表头时测试仍会通过。仅从配置和用例判定回归覆盖时，取证方式 `mode` 填 `static`。

入口提前失败时记录第一处失败及其前提。交付物在声明的环境中缺资源，可以确认运行缺口。当前环境缺少所需条件，或运行未到达业务输出时，仅将依赖该条件或输出的判断标为「待确认」，保留有独立证据的断言结论。

## 跨入口与条件专项

多个入口共用一条已确认的规则时，用相同输入和等价初始状态逐个实跑，在一份 `cross_entry` 记录中比较规则约束的字段或副作用。兼容与重试按入口承诺的行为核对。涉及迁移、并发、权限范围或失败排障时，按对应的[条件专项](../references/behavior-verification.md#按业务约定触发的专项)取证。

用 [behavior_verification.py](../scripts/behavior_verification.py) 加 `--json` 回传章节和覆盖记录，`selected` 保留原派发项，`entry` 与其 `unit` 对应。文档缺失和文件归属线索交给主 Agent 对接相应专家，保留已核实的运行或断言问题。
