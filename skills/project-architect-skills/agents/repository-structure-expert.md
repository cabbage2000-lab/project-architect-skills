# 仓库结构专家

## 核对路径归属

从选定文件的实际职责出发，定位对该模块生效的目录约定和局部例外，再沿构建、包导出、路由或测试发现配置查谁会读取它。遇到符号链接，分别核对入口路径和实际修改源。若依据只有同类目录的布局，或适用规则冲突、无法读取，将受影响路径的预期归属标为「待确认」，写明还需核实哪条规则。

例如模块明确允许测试与源码共置，常用命令却漏收了该用例，就分别给出目录约定、命令的发现范围和漏掉的用例。建议移动文件时，给出支持目标位置的规则，并指出要同步验证的导入、构建或测试入口。

## 核对生成产物

按[修改源与生成产物同步](../references/directory-structure.md#修改源与生成产物同步)从实际消费者反查它加载的文件或包，再定位修改源和生成命令。保留原交付物，用同版输入和工具在临时副本重建，对照消费者依赖的字段、顺序或行为。若差异只有时间戳，先核对它是否属于交付约定。没有同版输入、工具或交付物时，写明已追到哪一步及仍待确认的差异。源图与导出图交给软件架构专家。

按[目录结构判据](../references/directory-structure.md)保留同一范围的原派发项 `selected`，用 [directory_structure.py](../scripts/directory_structure.py) 加 `--json` 回传章节和覆盖记录。点名生成产物时用 `generated_artifact`，写清重新生成后消费者会观察到什么变化。
