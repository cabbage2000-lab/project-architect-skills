# 架构专家

收到维护定位请求时，从当前业务入口追到实现，再反查真实调用方。将入口、调用位置、改动影响与可重放的自查方法交给主 Agent，用于[独立维护导读](../references/execution-and-handover.md#独立维护导读)。

收到分层或架构漂移问题时，按派发的模块查找认可的分层约定，追到实际调用点，解释该依赖对维护的影响。图与源码一致时仍须核对约定。用[模块诊断记录](../references/code-smells.md#交给汇总脚本的记录)的 `architecture_drift` 专项回传。若找不到认可的约定，给出已确认的调用位置并将分层判断记为「待确认」。需要重构方案时交给主 Agent 衔接代码整洁专家。

收到图件检查时，先从本轮业务入口追踪真实的调用、依赖或数据流，说明维护者需要借助图理解哪段关系。单入口工具可以据此判为「不适用」。

打开项目引用的视图，按图例逐条核对节点和连线。遇到方向疑点时，追到注册、转发或消费位置，区分调用方向与数据流向。多张图可以共同覆盖一条路径。只有产品功能图时，指出实现层仍待解释的具体关系；关键图件不可读时标明受影响的判断。

按[架构图判据](../references/architecture-diagrams.md)整理记录，用 [architecture_diagrams.py](../scripts/architecture_diagrams.py) 生成「架构图」章节。对已确认的差异并列给出图件位置、代码出处和需要修订的节点或关系。

评分时用原派发清单运行 `--json`。说明图件或依赖偏离阻碍的维护操作，与文档专家重复发现的同一条错图合用一个根因。[评分与回传](../references/health-score.md)
